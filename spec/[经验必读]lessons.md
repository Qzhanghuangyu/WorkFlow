# [经验必读] 团队经验沉淀库（跨切面兜底）

> **读取必要性：经验必读。** propose / apply / archive 阶段必读。
> 本文是「反复纠正 → 蒸馏成的通用规则」的**兜底沉淀处**，只收**不属于任何单一阶段文档**的跨切面条目。
> 目标不是「记下所有纠正」，而是「收敛到一小撮高信号规则」——条目应越蒸馏越少、越通用，而不是流水账。

---

## 使用规则（先读这一段）

### 一条经验该放哪（放对位置才会被回忆）

**优先折叠进「那个阶段本来就会读」的文档，本文件是最后兜底：**

| 经验类型 | 落到 | 不要放进本文件 |
| --- | --- | --- |
| UI 选型 / 禁用 | `[UI控件必读]` 对应大类明细 | ✅ 折叠过去 |
| 需求分析盲点（老漏的检查项） | `[分析必读]preflight.md` | ✅ 折叠过去 |
| 实施规范（老犯的错） | `[模块选读]apply.md` | ✅ 折叠过去 |
| **跨阶段、不属于以上任何一个** | **本文件 `lessons.md`** | —— |

> 一条经验放错文件 = 永远不会被读到。先问「它属于哪个阶段？」——能归位就归位，只有真跨切面才留本文件。

### 写入纪律（防膨胀、防烂）

1. **蒸馏优先于追加**：写之前先查有没有已覆盖的条目；能并进 / 能让某条更通用，就**改它**，不要新增。
2. **去重 · 覆盖 · 删除**：新经验覆盖旧的；过期 / 被证伪的**直接删**。只增不删 = write-only = 迟早烂。
3. **每条写清 Why + How**：不只写「别做 X」，要写清缘由与适用条件，将来才知道它是否还成立。
4. **规范类由用户确认后再写**：错规则会被 hook 永久注入，比没有更糟——归档「经验萃取」时，规范类条目须经用户确认。
5. **条数是信号**：若本文件条目在线性增长，说明条目太具体（过拟合某一次），该再蒸馏，而不是继续堆。涨大了就照 `[UI控件必读]` 那样拆成 router + 大类。

### 什么时候写

- **归档阶段「经验萃取」**（主入口）：见 `[任务选读]archive.md`——一个 change 收尾时回顾本轮反复纠正的点，分类后路由到上表对应文档 / 本文件。
- **随手记一条**：过程中用户明确要求「记住这个」时，当场分类写到对的地方。

## 条目格式（复制填写）

```markdown
### <触发场景，一句话说清「什么情况下适用」>

- 规则：<该怎么做 / 禁止什么，明确可执行>
- Why：<为什么，来自哪次纠正 / 哪个坑>
- 反例（可选）：<以前的错误做法>
- 适用范围（可选）：<限定项目 / 模块 / 条件；无则视为通用>
```
