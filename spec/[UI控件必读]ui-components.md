# [UI控件必读] UI 控件映射约定库（路由入口）

> **读取必要性：UI 控件必读（本文是路由入口，务必先读本文）。**
> 本库把「UI 模式 → 指定实现」的团队经验，固化为 AI 可执行的规则。
> 为避免单文件无限膨胀，本库按**大类**拆成多个明细文件，放在同目录的 `ui-components/` 下。
> **本文只负责「分流」**：你只需读本文这一个小文件，判断当前控件属于哪个大类，再去读那一个大类明细。
>
> - **propose 阶段**：把 UI 大任务拆成模块控件时，每个控件先按下方「大类路由表」定位大类 → 读对应明细 → 命中的按「指定实现」写进 `design.md` / `tasks.md`。
> - **apply 阶段**：实施命中某大类的控件时，**必须**按该大类明细的指定实现，不得自选方案。
>
> 命中本库的控件，视为 [Must Read] soul.md 信条一中「可由 AI 高效完成的 80%」。
> **未命中任何大类，或命中了明细里「需人工裁定」条件的，不要擅自决定——按各条目要求暂停并交由用户裁定。**

---

## 使用规则（先读这一段，对所有大类通用）

1. **分流**：先看本文「大类路由表」，按「识别关键词 / 特征」判断当前控件属于哪个大类。
2. **只读命中的大类**：命中某大类 → **只读** `ui-components/<该大类文件>`，不必读其他大类文件；未命中任何大类 → 按常规流程设计，不要硬套。
3. **匹配条目**：进入大类明细后，按其中每条的「识别特征」定位到具体条目。
4. **标准情况**：符合条目「标准情况」的，直接采用「指定实现」。若当前项目中已有同类控件的实现，应在 `design.md` 引用它作为「参考实现」。
5. **复杂 / 变体情况**：命中条目里的「需人工裁定的情况」时，**不要自行发挥**——在 tasks/comate 中标注，并按 soul.md 的暂停约定请用户裁定后再实施。

> **本库为通用模板。** 各条目给出的是「指定实现 + 官方标准用法」；具体参考类路径、主题色、字号等，请在接入项目时补成该项目的真实实现（见每条「本项目参考实现」占位）。

## 如何扩展本库（维护约定）

- **新增一个控件**：找到它所属的大类，**在对应的 `ui-components/<大类>.md` 里追加一条**，沿用该文件内条目的统一结构（识别特征 / 指定实现 / 官方标准用法 / 标准情况+本项目参考实现 / 需人工裁定的情况 / 留给人工的 20%）。
- **新增一个大类**：在 `ui-components/` 下**新建一个 md**（命名用「大类中文-关键英文」，如 `表单-输入.md`），然后回到本文的「大类路由表」**加一行**指向它。
- 保持本文（路由）尽量精简：只放通用规则和路由表，**具体控件实现一律写进大类明细文件**，不要写回本文。
